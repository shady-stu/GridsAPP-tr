# دليل ملفات المشروع

هذا الدليل يشرح الملفات المضافة أو التي تغيرت عند بناء لوحة Northstar. يمكن فتح الأمثلة من الجذر `react-quality-project`.

## مسار البيانات بين الطبقات

```text
مصدر تجريبي أو HTTP مستقبلي (unknown)
  → schemas.ts: فحص Zod وإنتاج أنواع موثوقة
  → provider.ts: نتيجة نجاح أو خطأ typed
  → App.tsx: تحميل البيانات وإرسال الأحداث
  → dashboardReducer.ts: الحالة المشتركة وانتقالات صريحة
  → DataTable وOrderForm: عرض وتفاعل
  → DOM للمستخدم
```

مدخل النموذج يبدأ كنصوص، ثم يتحقق منه مخطط Zod قبل استدعاء المزود. المزود يعدّل نسخة ذاكرة محلية، وبعد نجاحه يرسل النموذج الطلب إلى reducer ليظهر في الجدول. النشاط ينشأ مرة واحدة في مزود البيانات؛ reducer لا يكرر نشاطاً موجوداً ولا يدعي دواماً بعد إعادة التحميل.

## ملفات التطبيق

### `src/domain/schemas.ts` — المخططات وأنواع المجال

يوحّد Zod مخطط البيانات وقواعدها وقت التشغيل، ومنه تشتق `Customer` و`Order` و`Activity` والأنواع ذات الصلة عبر `z.infer`. يوجد مخطط مستقل لمدخل الطلب لأن قيم عناصر HTML نصوص حتى عندما تمثل مبلغاً رقمياً. هذا فحص وقت تشغيل، بينما TypeScript يحمي الاستخدام داخل البرنامج وقت البناء فقط. عند إضافة حقل عميل أضفه إلى `customerSchema`، وعدّل بيانات المزود والواجهة والاختبارات؛ الأنواع المستنتجة تتحدث تلقائياً. مثال: `customerSchema.shape.name` يتيح فحص قاعدة الاسم دون تكرار الواجهة.

### `src/data/provider.ts` — واجهة البيانات ومحول العرض التجريبي

يعرف `DashboardProvider` العقد الذي تعتمد عليه الواجهة، و`Result<T>` اتحاداً مميزاً بين النجاح والخطأ. البيانات التجريبية تبدأ كـ`unknown` ثم تمر بـ`parseDashboardPayload`. يحفظ `createDemoProvider` نسخة ذاكرة خاصة به، وينشئ النشاط مرة واحدة عند نجاح الطلب. استبدل تنفيذ هذا الملف بطلب `fetch` مستقبلي مع فحص HTTP وJSON وZod، وأبقِ عقد الواجهة. لا تستخدم `as DashboardData` مع استجابة شبكة؛ ذلك لا يتحقق من البيانات.

### `src/state/dashboardReducer.ts` — الحالة المشتركة

يمثل `LoadState` التحميل والخطأ والنجاح كحالات منفصلة، لذلك لا يمكن للواجهة اعتبار بيانات غير محملة بيانات صالحة. اتحاد `DashboardAction` يحدد كل انتقال. `dashboardReducer` يعالج بدء التحميل والنجاح والفشل والاختيار والطلب المنشأ، وحالة `never` تكشف عند البناء أي فعل جديد لم يعالج. لا تخزن هنا القيم المشتقة مثل الإيراد؛ احسبها من الطلبات.

### `src/components/DataTable.tsx` — جدول عام

يمثل `DataTable<T>` نوع الصف، وتعتمد أعمدة `Column<T>` على النوع نفسه، ما يجعل `render` آمن الأنواع. `rowKey` يوفر معرفاً مستقراً ولا يعتمد على رقم الصف. يعرض مكون الجدول عناصر HTML دلالية وحالة فراغ، ويعيد استخدامه التطبيق لعميل ولطلب. عند إضافة عمود، أضف `Column<Order>` أو `Column<Customer>` في موضع استخدامه ولا تضع منطق المجال في الجدول العام.

### `src/components/OrderForm.tsx` — نموذج الطلب

يمتلك المدخلات والأخطاء وحالة الإرسال المؤقتة عبر `useState`. عند الإرسال يمنع السلوك الافتراضي والإرسال المكرر، ثم يتحقق من الإدخال، وينادي عقد المزود، ويستدعي `onCreated` بعد النجاح فقط. الأخطاء مرتبطة بالحقول بـ`aria-describedby` وتعرض الحالة بـ`role=status`. رفض المزود لا يمسح المدخلات ولا يظهر رسالة نجاح؛ والاستثناء غير المتوقع يعرض رسالة قابلة لإعادة المحاولة.

### `src/App.tsx` — تركيب الصفحة والاشتقاقات

يملك `useReducer` البيانات المشتركة، ويستخدم `useEffect` لمزامنة التحميل مع مصدر خارجي غير متزامن فقط. تستخدم `useMemo` لتصفية الطلبات، وتحسب الإحصائيات مباشرة من البيانات الجاهزة. يعرّف التطبيق مجموعتي أعمدة جدول مختلفتين ويوصل النموذج بالمزود. شاشة الخطأ تتضمن إعادة محاولة، وشاشة التحميل تسبق الجدول. عند ظهور حقل جديد، حدّث المخطط أولاً ثم أضف طريقة عرضه والاختبارات.

### `src/App.css` و`src/index.css` — العرض والتجاوب

تعرف CSS مكونات اللوحة وتخطيط الشاشات الصغيرة، كما تدعم تقليل الحركة والطباعة. تبقى قواعد التطبيق المرئية في `App.css` وقواعد المستند العامة في `index.css`. قيم التصميم عرضية وليست بيانات فعلية؛ لا تخزن حالة التطبيق في CSS.

### `src/main.tsx` و`index.html` — نقطة التشغيل

`main.tsx` يركب React داخل عنصر الجذر ويشغّل الوضع الصارم. يحمل `index.html` بيانات الصفحة الوصفية والعنصر الذي يركب فيه React. يظل التحقق من البيانات داخل حدود المجال والمزود، لا داخل HTML.

## الأدوات والتكوين

### `package.json` و`package-lock.json`

يحدد الأول التبعيات والأوامر، ويحفظ الثاني إصدارات التثبيت الدقيقة المستخدمة في `npm ci`. الأوامر: `typecheck` و`lint` و`format:check` و`test` و`build`؛ الأمر `ci` يجمعها بالتتابع. بعد تعديل تبعية حدّث lockfile مع مدير الحزم.

### `vite.config.ts` و`tsconfig.app.json` و`eslint.config.js`

تحدد هذه الملفات بيئة Vitest DOM وتحميل إعداد الاختبار، وفحص TypeScript الصارم، وقواعد ESLint. لا يلزم تعريف Zod في تكوين منفصل؛ المخططات في المجال.

### `.github/workflows/ci.yml`

يشغّل على GitHub Actions تثبيتاً قابلاً للإعادة بواسطة `npm ci` ثم الأنواع وESLint وPrettier والاختبارات والبناء. يجب أن تظل خطوات workflow مطابقة لأسماء scripts الموجودة.

### `README.md`

صفحة تشغيل ونظرة معمارية وحدود العرض التجريبي. ابدأ بها لتشغيل المشروع، ثم استخدم هذا الدليل لفهم الملفات.
