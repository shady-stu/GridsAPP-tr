# مسار تعلم المشروع

اتبع الترتيب التالي. لكل مرحلة مثال من التطبيق وتمرين وسؤال للتحقق من الفهم.

## ١. معمارية المشروع وتدفق البيانات

**المشكلة:** كيف تبقى الشاشة ومصدر البيانات متزامنين دون ربطهما مباشرة؟ **الفكرة:** طبقات صغيرة؛ مخطط، مزود، حالة، ثم عرض. **الموضع:** `src/domain/schemas.ts` ← `src/data/provider.ts` ← `src/state/dashboardReducer.ts` ← `src/App.tsx`.

```text
unknown → Zod parse → Result<DashboardData> → reducer → UI
```

**تمرين:** تتبع طلباً من الضغط على زر الإنشاء حتى صف الجدول. **تحقق:** في أي طبقة تحفظ البيانات التجريبية؟

## ٢. أنواع المجال في TypeScript

**المشكلة:** منع ربط طلب بعميل غير متوافق أو إرسال حالة طلب غير معروفة. **الفكرة:** الأنواع تصف قيم المجال وعلاقاتها، مثل `Order.customerId` الذي يشير إلى `Customer.id`. **الموضع:** `schemas.ts`.

```ts
type Order = z.infer<typeof orderSchema>;
type CustomerName = Customer["name"];
```

المثال الثاني يستخدم الوصول المفهرس. **تمرين:** أضف `phone` إلى العميل وتتبّع أخطاء البناء. **تحقق:** هل `string` في TypeScript يفحص أن البريد صالح أثناء التشغيل؟ لا؛ المخطط يفعل ذلك.

## ٣. التحقق وقت التشغيل باستخدام Zod

**المشكلة:** البيانات القادمة من شبكة أو مدخل المستخدم قد تخالف النوع المتوقع. **الفكرة:** تعامل معها كـ`unknown`، ثم افحصها عند الحد باستخدام `safeParse`. **الموضع:** `schemas.ts`, `provider.ts`, `OrderForm.tsx`.

```ts
const parsed = dashboardDataSchema.safeParse(payload);
if (!parsed.success)
  return { success: false, error: { message: "Invalid data" } };
return { success: true, data: parsed.data };
```

**تمرين:** اجعل مخطط العميل يقبل هاتفا اختيارياً. **تحقق:** لماذا لا يكفي cast من `unknown` إلى `Customer`؟

## ٤. تصميم مزود البيانات

**المشكلة:** تجنب أن تعرف الواجهة تفاصيل التخزين أو HTTP. **الفكرة:** عقد `DashboardProvider` ونتيجة typed تفصل التطبيق عن المحول. **الموضع:** `provider.ts`.

```ts
type Result<T> =
  { success: true; data: T } | { success: false; error: { message: string } };
```

**تمرين:** نفّذ مزوداً وهمياً يفشل في التحميل. **تحقق:** ما الفحص الإضافي الذي يحتاجه JSON عند توصيل HTTP حقيقي؟ افحص حالة HTTP ونجاح تحليل JSON ومخطط Zod.

## ٥. الاتحادات المميزة و`never`

**المشكلة:** منع وجود حالة تحميل وخطأ ونجاح متداخلة أو ناقصة. **الفكرة:** حقل `status` يميز كل شكل، و`never` يتحقق من اكتمال `switch`. **الموضع:** `dashboardReducer.ts`, `App.tsx`.

```ts
type LoadState = { status: "loading" } | { status: "error"; message: string };
```

**تمرين:** أضف حالة empty وحدّث عرض الواجهة. **تحقق:** ما الذي يكشفه فحص `never` بعد إضافة فعل جديد؟

## ٦. `useReducer` وانتقالات الحالة

**المشكلة:** صعوبة تتبع تغييرات بيانات مشتركة عندما تكون التحديثات موزعة. **الفكرة:** أفعال مسماة تقلل الحالة عبر reducer نقي. **الموضع:** `dashboardReducer.ts` و`App.tsx`.

```ts
dispatch({ type: "customer-filter-changed", customerId: "cus-02" });
```

**تمرين:** أضف فعلاً لإعادة تعيين التصفية. **تحقق:** أين تحفظ أخطاء حقل مؤقتة، في reducer أم النموذج؟

## ٧. مكونات React العامة

**المشكلة:** تكرار جدول العرض لكل نوع مجال مع فقدان فحص الأنواع. **الفكرة:** `DataTable<T>` يحمل النوع نفسه من الصف عبر الصفوف والأعمدة ومفتاح الصف.

```tsx
<DataTable
  rows={orders}
  columns={orderColumns}
  rowKey={(row) => row.id}
  label="Orders"
  emptyMessage="No orders"
/>
```

**تمرين:** اعرض العملاء بالجدول نفسه مع بريدهم. **تحقق:** كيف يستنتج TypeScript نوع `row` داخل `render`؟

## ٨. النماذج المضبوطة ومعالجة الأخطاء

**المشكلة:** DOM قد يحمل مدخلات غير صالحة أو يرسل أكثر من مرة. **الفكرة:** controlled input، تحقق عند الحد، تعطيل أثناء الإرسال، وحالة خطأ أو نجاح واضحة. **الموضع:** `OrderForm.tsx`.

```tsx
<input
  value={description}
  onChange={(event) => setDescription(event.target.value)}
/>
```

**تمرين:** أضف حد أقصى لطول الوصف في Zod والرسالة المرتبطة به. **تحقق:** متى يعرض النموذج إعلان النجاح؟ بعد رد المزود الناجح.

## ٩. الحالة المشتقة وReact effects

**المشكلة:** تخزين أرقام مشتقة قد يجعلها قديمة. **الفكرة:** احسب الإيراد من الطلبات، واستخدم effect فقط لمزامنة مصدر خارجي. **الموضع:** `App.tsx`.

```ts
const revenue = orders
  .filter((order) => order.status === "completed")
  .reduce((sum, order) => sum + order.amount, 0);
```

**تمرين:** احسب متوسط قيمة الطلبات المكتملة دون تخزينه. **تحقق:** لماذا يستخدم التحميل `useEffect`؟ لأنه عملية غير متزامنة خارجية عن العرض.

## ١٠. اختبارات الوحدات والمكونات

**المشكلة:** تغييرات صغيرة قد تكسر السلوك المرئي. **الفكرة:** اختبر نتائج المخططات والـDOM وتفاعلات المستخدم، واعزل حد البيانات. **الموضع:** ملفات `*.test.ts(x)`.

```ts
expect(await screen.findByText("Recent orders")).toBeInTheDocument();
```

**تمرين:** اختبر بحث العميل الذي لا يعيد نتائج. **تحقق:** ما فائدة `user-event` مقارنة باستدعاء handler داخلي؟ يحاكي تفاعلاً أقرب لسلوك المستخدم.

## ١١. أدوات جودة الكود والبناء

**المشكلة:** قد يعمل التطبيق محلياً رغم وجود أخطاء أنواع أو تنسيق أو إنتاج. **الفكرة:** فحوص مستقلة ثم CI يستخدم التبعيات المقفلة.

```bash
npm run typecheck
npm run lint
npm run format:check
npm run test
npm run build
```

**تمرين:** أنشئ تغييراً منسقاً خطأ ولاحظ فشل `format:check` ثم أصلحه. **تحقق:** أي أمر ينتج ملفات النشر؟ `build`.
