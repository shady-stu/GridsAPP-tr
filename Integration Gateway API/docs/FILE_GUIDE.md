# دليل ملفات المشروع

هذا الدليل يشرح الوحدات ومسار البيانات وطرق التوسعة؛ لا يكرر محتوى ملفات المصدر. الشرح هنا بالعربية، أما أسماء الأنواع والدوال والمسارات والأمثلة البرمجية فتبقى بالإنجليزية لتطابق المشروع.

## نقطة التركيب والتشغيل

### `src/app.ts`

1. **المسؤولية والسبب:** تركيب Fastify وحدود الوحدات، لا تنفيذ قواعد العملاء أو الطلبات. يفصل هذا الملف البناء عن منطق الأعمال.
2. **الوارد والصادر:** يستورد إعدادات Fastify والقاعدة والإضافات والمسارات. يصدر `AppOptions` و`BuiltApp` و`buildApp`، ويعيد تصدير `signWebhook` توافقًا مع مسار الاستيراد السابق.
3. **الأنواع والدوال:** `AppOptions` يسمح بحقن مسار DB وساعة اختبار؛ `BuiltApp` يضيف `db` و`processPendingEvents`.
4. **التدفق والاعتمادات:** يفتح DB، يسجل Swagger وrate limit، يركب parser والمصادقة والأخطاء، ثم يسجل health/customers/orders/webhooks، وأخيرًا يشغل عامل الأحداث.
5. **TypeScript/Fastify والأمان:** `ReturnType<typeof Fastify>` يحافظ على نوع نسخة Fastify الفعلية. الأسرار تمر للإضافات دون تضمينها في الاستجابة.
6. **مثال التوسعة:** أضف `registerInventoryRoutes(app, { db })` هنا بعد إنشاء DB، وضع قواعد المخزون داخل مجلد وحدته.
7. **تجنب:** لا تضف SQL أو تحققًا خاصًا بمورد هنا؛ ولا تجعل وحدة تستورد `app.ts` لأن ذلك يقلب اتجاه الاعتماد وقد يصنع دورة.

### `src/server.ts`

1. **المسؤولية والسبب:** نقطة تنفيذ عملية الإنتاج والاستجابة لإشارات الإيقاف.
2. **الوارد والصادر:** يستورد `config` و`buildApp`؛ لا يصدر واجهة عامة.
3. **الأنواع والدوال:** `shutdown(signal)` يغلق Fastify مرة واحدة ويحمي من إشارتين متزامنتين.
4. **التدفق:** يبني التطبيق، يسجل SIGINT/SIGTERM، يستمع على HOST/PORT؛ إذا فشل الاستماع يغلق DB والعامل.
5. **المفاهيم والأمان:** `process.once` يمنع تكرار الإغلاق؛ الإغلاق ينتقل إلى hook `onClose`.
6. **التوسعة:** اربط مراقبة readiness قبل `listen` أو أضف تهيئة تعتمد على البيئة هنا.
7. **تجنب:** لا تنشئ Fastify آخر داخل المسارات ولا تتجاهل `app.close()` عند الإنهاء.

### `src/config.ts`

1. **المسؤولية والسبب:** تحميل `.env` والتحقق من قيم البيئة مرة واحدة عند الاستيراد.
2. **الوارد والصادر:** يستخدم `dotenv/config` وZod؛ يصدر `config` و`Config`.
3. **الأنواع والدوال:** `Config` نوع ناتج من مخطط Zod بعد القيم الافتراضية والتحويل الرقمي.
4. **التدفق:** يقرأ `process.env`، يرفض أول التشغيل إذا نقص سر أو خرج رقم عن المجال، ولا يعرض القيم.
5. **المفاهيم والأمان:** `z.coerce.number()` يحول متغير البيئة النصي إلى رقم؛ لا تُطبع الأسرار عند فشل التحقق.
6. **التوسعة:** أضف المتغير إلى Zod و`.env.example` والجدول في README في التغيير نفسه.
7. **تجنب:** لا تضف قيمة سر حقيقية كـdefault ولا توثق متغيرًا غير موجود في المخطط.

### `src/database.ts`

1. **المسؤولية والسبب:** فتح SQLite وتهيئة schema والفهارس المتوافقة مع restart.
2. **الوارد والصادر:** يستخدم `better-sqlite3` وعمليات المسارات؛ يصدر `openDatabase` و`Db`.
3. **الأنواع والدوال:** `openDatabase(path)` يعيد اتصالًا؛ `Db` نوع هذا الاتصال.
4. **التدفق:** ينشئ مجلد الملف، يفعّل WAL والمفاتيح الأجنبية، ثم ينفذ `CREATE TABLE IF NOT EXISTS`.
5. **المفاهيم والأمان:** `:memory:` يعزل الاختبارات؛ أعمدة idempotency لها قيد مركب principal/key وevent id مفتاح فريد.
6. **التوسعة:** أضف migration/version عند تغيير schema الإنتاجي بدل تعديل الجداول بصمت.
7. **تجنب:** لا تمرر أسماء أعمدة من المستخدم إلى SQL، ولا تغلق الاتصال من route.

## أدوات HTTP والإضافات

### `src/lib/http.ts`

1. **المسؤولية والسبب:** أدوات مشتركة لتوحيد التحقق والأخطاء والمصادقة وتسجيل route metadata.
2. **الوارد والصادر:** يعتمد على Fastify وZod ونوع `Principal`؛ يصدر `failure` و`parse` و`requirePrincipal` و`sendFailure` و`addApiRoute`.
3. **الأنواع والدوال:** `ApiFailure` و`Parsed<T>` يعبران عن نتيجة ناجحة أو رد خطأ.
4. **التدفق:** `parse` يستدعي `safeParse`؛ `requirePrincipal` يرد 401/403؛ `addApiRoute` يربط وصف OpenAPI بمسار.
5. **المفاهيم والأمان:** `Parsed<T>` discriminated union يُفحص بـ`"response" in parsed`. `attachValidation` يترك Zod يحدد عقد الخطأ.
6. **التوسعة:** أضف pagination مشتركة هنا فقط إذا احتاجتها عدة وحدات فعلًا.
7. **تجنب:** لا تخزن هوية داخل هذا الملف ولا تجعل رسائل الخطأ تكشف تفاصيل SQL.

### `src/lib/errors.ts`

1. **المسؤولية والسبب:** تجميع معالجة 404 وأخطاء الحجم والتحقق والاستثناءات.
2. **الوارد والصادر:** يعتمد على `FastifyInstance`؛ يصدر `registerErrorHandlers`.
3. **الأنواع والدوال:** لا يضيف أنواع HTTP عامة؛ يسجل Fastify handlers.
4. **التدفق:** يقرأ statusCode وvalidation من Fastify، يبني fields إذا وجدت، ويسجل الأخطاء غير المعروفة داخليًا ثم يرسل رسالة آمنة.
5. **المفاهيم والأمان:** `Error & { statusCode? }` يضيق نوع Fastify للحقول المقروءة؛ الاستجابة لا تحمل stack trace.
6. **التوسعة:** عالج رمز خطأ جديد هنا مع غلاف ثابت، ثم أضف اختبار pipeline له.
7. **تجنب:** لا تعِد `error.message` الخام إلى العميل.

### `src/lib/schemas.ts`

1. **المسؤولية والسبب:** مخططات صغيرة مشتركة لاختبارات المعرفات.
2. **الوارد والصادر:** يعتمد على Zod؛ يصدر `uuidSchema`.
3. **الأنواع والدوال:** مخطط UUID قابل للاستيراد من مخططات العملاء والطلبات.
4. **التدفق:** يستدعيه مخطط المورد قبل الاستعلام.
5. **المفاهيم والأمان:** التحقق الصارم يمنع تمرير معرف غير صالح إلى قاعدة البيانات.
6. **التوسعة:** أضف فقط قواعد عامة مطلوبة في أكثر من وحدة.
7. **تجنب:** لا تضع مخطط حدث الدفع هنا؛ مكانه وحدة الويب هوك.

### `src/plugins/authentication.ts`

1. **المسؤولية والسبب:** تحويل token مُهيأ إلى principal خادمي على الطلب.
2. **الوارد والصادر:** يعتمد على `Config` و`constantTimeEqual`؛ يصدر `registerAuthentication` ويضيف خصائص FastifyRequest عبر declaration merging.
3. **الأنواع والدوال:** `Principal` يحدد id وrole؛ `request.principal` nullable.
4. **التدفق:** يضيف `x-request-id`، يقرأ Bearer، يقارن الرموز، ويعين دورًا ثابتًا.
5. **المفاهيم والأمان:** Declaration merging يوسّع نوع الطلب؛ لا يُقرأ user id أو role من جسم العميل.
6. **التوسعة:** استبدل المطابقة الثابتة بمتحقق issuer عند ربط مزود هوية، مع إبقاء واجهة `Principal`.
7. **تجنب:** لا تسجل token ولا تقبل role من query أو body.

### `src/plugins/raw-json.ts`

1. **المسؤولية والسبب:** إبقاء البايتات الأصلية للجسم مع إتاحة JSON محلل لبقية المسارات.
2. **الوارد والصادر:** يعتمد على Fastify؛ يصدر `registerRawJsonParser` ويكتب `request.rawBody` الذي عرّفه plugin المصادقة.
3. **الأنواع والدوال:** parser من نوع Buffer؛ يحلل إلى unknown قبل تسليمه لـFastify.
4. **التدفق:** يحول البايتات إلى UTF-8، يحفظ Buffer أولًا، ثم يحلل JSON؛ malformed JSON يمر إلى معالج الأخطاء.
5. **المفاهيم والأمان:** الترتيب يحفظ exact bytes للتوقيع؛ Fastify يطبق حد 1 MiB.
6. **التوسعة:** أضف parser لنوع محتوى جديد مع تحديد واضح لما يعتبره مزود التوقيع bytes.
7. **تجنب:** لا تعِد تسلسل object قبل HMAC ولا تسجل الجسم الحساس.

## وحدات الموارد

### `src/modules/health/routes.ts`

1. **المسؤولية والسبب:** إبقاء health route خارج وحدات الأعمال.
2. **الوارد والصادر:** يعتمد على `addApiRoute`؛ يصدر `registerHealthRoute`.
3. **الأنواع والدوال:** يسجل `GET /health`.
4. **التدفق:** يعيد `{ data: { status: "ok" } }` بلا مصادقة أو قراءة DB.
5. **المفاهيم والأمان:** route عام ومناسب لفحص process فقط؛ لا يثبت توافر مزود خارجي.
6. **التوسعة:** أضف readiness منفصلة إذا لزم فحص DB.
7. **تجنب:** لا تكشف تفاصيل host أو اتصال قاعدة البيانات في health العام.

### `src/modules/customers/schemas.ts`

1. **المسؤولية والسبب:** عقد Zod لأجسام العميل ومعاملاته وقائمته.
2. **الوارد والصادر:** يعتمد على Zod و`uuidSchema`؛ يصدر مخططات الإدخال والتعديل والاستعلام والنوع `CustomerInput`.
3. **الأنواع والدوال:** `customerInputSchema` صارم، `customerPatchSchema` يمنع التعديل الفارغ، والقائمة تضبط الفرز والصفحات.
4. **التدفق:** يستدعيها route قبل قاعدة البيانات.
5. **المفاهيم والأمان:** `z.infer` يستخرج النوع من عقد وقت التشغيل؛ أعمدة sort محصورة بقيم الاتحاد.
6. **التوسعة:** أضف حقلًا هنا ثم عدّل serializer والاختبار وتوثيق OpenAPI.
7. **تجنب:** لا تجعل client يرسل owner id؛ الملكية تأتي من principal.

### `src/modules/customers/serializers.ts`

1. **المسؤولية والسبب:** تحويل صف DB إلى response public.
2. **الوارد والصادر:** دالة `serializeCustomer` لا تعتمد على Fastify.
3. **الأنواع والدوال:** تقبل `Record<string, unknown>` وتعيد الحقول المختارة.
4. **التدفق:** route يمرر الصف ثم يضع النتيجة داخل `data`.
5. **المفاهيم والأمان:** allowlist للحقول تمنع تسرب `owner_id` أو حقول تخزين مستقبلية.
6. **التوسعة:** أضف الحقل العام إلى هذا serializer والمخطط في الوقت نفسه.
7. **تجنب:** لا تستخدم `{ ...row }` على صف قاعدة البيانات.

### `src/modules/customers/routes.ts`

1. **المسؤولية والسبب:** CRUD للعملاء مع صلاحيات المالك.
2. **الوارد والصادر:** يعتمد على Db وأدوات HTTP والمخططات والserializer؛ يصدر `registerCustomerRoutes`.
3. **الأنواع والدوال:** `CustomerRoutesOptions` يحقن DB وساعة الوقت.
4. **التدفق:** كل handler يطلب principal، يتحقق من المدخل، يحد الاستعلام بالمالك، ثم يعيد serializer. الحذف الإداري يحذف الطلبات والعميل داخل transaction.
5. **المفاهيم والأمان:** أسماء sort من الاتحاد تتحول لخريطة أعمدة ثابتة؛ قيم SQL مربوطة parameterized؛ أخطاء unique email فقط تصبح 409.
6. **التوسعة:** أضف endpoint من خلال `addApiRoute` واستخدم مخططًا وserializer منفصلين.
7. **تجنب:** لا تعِد 409 لكل خطأ DB؛ لا تزل شرط owner من أي get/update.

### `src/modules/orders/schemas.ts`

1. **المسؤولية والسبب:** مخططات الطلب والمدخلات والحالة والفرز.
2. **الوارد والصادر:** يعتمد على Zod و`uuidSchema`؛ يصدر schemas العامة.
3. **الأنواع والدوال:** المخطط يضبط currency وstatus والحدود العددية.
4. **التدفق:** يتحقق قبل إنشاء بصمة المفتاح أو تشغيل الاستعلام.
5. **المفاهيم والأمان:** القيم الافتراضية تصبح جزءًا من payload الذي تُحسب بصمته.
6. **التوسعة:** أضف حالة جديدة في المخطط والمعالج والتوثيق والاختبارات معًا.
7. **تجنب:** لا تقبل اسم sort كعمود SQL مباشر.

### `src/modules/orders/serializers.ts`

1. **المسؤولية والسبب:** تحديد شكل الطلب العام دون خصائص التخزين.
2. **الوارد والصادر:** يصدر `serializeOrder` مستقلًا عن DB driver.
3. **الأنواع والدوال:** يعيد customerId والحالة والمجموع والعملة والطوابع الزمنية.
4. **التدفق:** يستخدم في get/list/update بدل إعادة صف SQL.
5. **المفاهيم والأمان:** لا يعرض `owner_id` أو أعمدة idempotency.
6. **التوسعة:** أضف تمثيلًا عامًا ثابتًا لحقل جديد.
7. **تجنب:** لا تمرر صف DB كاملًا للعميل.

### `src/modules/orders/routes.ts`

1. **المسؤولية والسبب:** CRUD للطلبات ومنع تكرار الإنشاء.
2. **الوارد والصادر:** يعتمد على crypto وDB وHTTP وأسماء schemas/serializers؛ يصدر `registerOrderRoutes`.
3. **الأنواع والدوال:** `OrderRoutesOptions` يحقن `db` و`now` و`epoch`؛ `replayOrConflict` خاص بإعادة الاستجابة.
4. **التدفق:** يقيّد القوائم والموارد بالمالك، يتحقق من ملكية customer، ثم يحفظ order والمفتاح والاستجابة داخل transaction.
5. **المفاهيم والأمان:** `createHash` يبصم Zod output. القيد الفريد يعالج السباق ويعاد منه للنتيجة المحفوظة. معاملات SQL تحمي قيم المستخدم.
6. **التوسعة:** أضف workflow جديدًا في module الطلبات وحافظ على scope principal في كل استعلام.
7. **تجنب:** لا تنشئ order قبل التحقق من idempotency والملكية، ولا تغير شكل الاستجابة المحفوظة بلا versioning.

### `src/modules/webhooks/schemas.ts`

1. **المسؤولية والسبب:** صيغة الحدث المقبولة.
2. **الوارد والصادر:** يعتمد على Zod وUUID المشترك؛ يصدر `paymentStatusEventSchema` و`PaymentStatusEvent`.
3. **الأنواع والدوال:** الحدث المسموح هو `payment.status_changed` وحالة الطلب المحصورة.
4. **التدفق:** يتحقق منه route بعد التوقيع، ثم يعيد المعالج التحقق من الصف المخزن.
5. **المفاهيم والأمان:** strict objects ترفض الخصائص غير المتوقعة، والنوع المشتق يجعل شكل الحدث موحدًا.
6. **التوسعة:** أضف event type صريحًا وقواعد معالجة واختبارًا لكل type جديد.
7. **تجنب:** لا تحلل event قبل التحقق من HMAC عند الاستقبال.

### `src/modules/webhooks/routes.ts`

1. **المسؤولية والسبب:** التحقق من ترويسات التوقيع وحفظ التسليم.
2. **الوارد والصادر:** يعتمد على config وDB وHTTP وsecurity وschema؛ يصدر `registerWebhookRoutes`.
3. **الأنواع والدوال:** `WebhookRoutesOptions` يحقن config والساعة.
4. **التدفق:** يفحص timestamp، يقارن HMAC على rawBody، يتحقق من الحدث، ثم INSERT OR IGNORE ويرد 202 أو 200 للتكرار.
5. **المفاهيم والأمان:** `constantTimeEqual` لا يقارن أسرارًا متفاوتة الطول بمسار متساوي؛ SQLite تحفظ الحدث قبل الإقرار.
6. **التوسعة:** اربط مصدر توقيع آخر عبر key id منفصل بعد إضافة عقد ترويسة موثق.
7. **تجنب:** لا تستخدم JSON.stringify لتكوين مادة التوقيع ولا تعِد 202 قبل نجاح التخزين.

### `src/modules/webhooks/processor.ts`

1. **المسؤولية والسبب:** فصل أثر الأعمال عن استقبال HTTP.
2. **الوارد والصادر:** يعتمد على Db ومخطط الحدث؛ يصدر factory `createWebhookProcessor` التي تعيد `processPendingEvents`.
3. **الأنواع والدوال:** `WebhookProcessorOptions` يضبط DB والوقت والحد الأعلى.
4. **التدفق:** يقرأ دفعة مستحقة، يحلل الصف، يحدث الطلب وعلامة processed معًا، أو يزيد المحاولات ويجدول التالي/dead letter.
5. **المفاهيم والأمان:** معاملة SQLite تسد نافذة الانقطاع بين الأثر وعلامة الإنجاز؛ التأخير أسي ومحدود ودفعة القراءة 50.
6. **التوسعة:** أضف تفاصيل قياس وإعادة تشغيل إدارية مع صلاحية تدقيق منفصلة.
7. **تجنب:** لا تصف المؤقت بأنه طابور موزع؛ لا تشغل عدة pollers على DB واحدة دون lease.

## أدوات مساعدة واختبارات

### `src/security.ts`

1. **المسؤولية والسبب:** primitives الأمنية المحدودة والمشتركة.
2. **الوارد والصادر:** يستخدم `node:crypto`؛ يصدر `Principal` و`constantTimeEqual` و`signWebhook`.
3. **الأنواع والدوال:** `signWebhook(secret, timestamp, rawBody)` تعيد hex، و`Principal` يحدد role.
4. **التدفق:** المصادقة تستدعي مقارنة token، route تستدعي التوقيع على timestamp وraw body.
5. **المفاهيم والأمان:** HMAC-SHA256، مقارنة ثابتة الزمن، واستبعاد user-supplied identity.
6. **التوسعة:** حافظ على تنسيق التوقيع المتفق عليه واختبره مقابل مثال موثق.
7. **تجنب:** لا تخزن السر هنا ولا تسجل النص الموقع.

### `src/scripts/sign-webhook.ts`

1. **المسؤولية والسبب:** أداة تشغيلية للتوقيع المحلي.
2. **الوارد والصادر:** يستخدم config و`signWebhook`؛ يقرأ body من CLI ويطبع timestamp/signature/body.
3. **الأنواع والدوال:** لا يصدر دوال؛ ينفذ كـtsx عبر npm script.
4. **التدفق:** يرفض غياب body، يولد epoch seconds، ثم يطبع حقول الإرسال.
5. **المفاهيم والأمان:** يعمل بالسر الموجود في `.env`؛ المخرجات حساسة ويجب عدم مشاركتها خارج بيئة الاختبار.
6. **التوسعة:** أضف خيار ملف إذا احتجت أجسامًا طويلة مع الحفاظ على البايتات.
7. **تجنب:** لا تضع webhook secret في command line أو المستودع.

### `src/types/better-sqlite3.d.ts`

1. **المسؤولية والسبب:** تعريف محلي محدود لمكتبة SQLite التي لا توفر الأنواع المثبتة في الحزمة.
2. **الوارد والصادر:** يعلن module `better-sqlite3` لأجل TypeScript.
3. **الأنواع والدوال:** يعرّف Database وStatement والعمليات المستخدمة فعليًا.
4. **التدفق:** TypeScript يقرأ الإعلان عند استيراد `database.ts`.
5. **المفاهيم والأمان:** declaration file يصف العقد فقط ولا يضيف runtime code؛ `unknown` يجبر المستهلك على تضييق نتيجة الصف.
6. **التوسعة:** أضف توقيعًا عند استخدام API جديدة بعد مراجعة تعريف المكتبة.
7. **تجنب:** لا توسع التواقيع إلى `any` ولا تدّع أنواعًا لا يدعمها runtime.

### `tests/integration/api.test.ts`

1. **المسؤولية والسبب:** اختبار Fastify request pipeline end-to-end داخل العملية.
2. **الوارد والصادر:** يستخدم Vitest و`buildApp` و`signWebhook`؛ لا يعتمد على شبكة أو مزود حقيقي.
3. **الأنواع والدوال:** helpers `customer` و`order` و`webhook`، config اختبار ثابت، وclock حتمي.
4. **التدفق:** ينشئ app وقاعدة `:memory:` لكل اختبار، يرسل inject، ثم يغلق التطبيق.
5. **المفاهيم والأمان:** يختبر owner scope وHMAC على bytes متفاوتة whitespace ومفتاح التكرار ومعاملة الإغلاق.
6. **التوسعة:** أضف اختبار HTTP-visible عند إضافة endpoint أو تغيير استجابة.
7. **تجنب:** لا تحذف assertion لإخفاء فشل ولا تختبر helper وحده بدل دورة الطلب.

### `src/app.ts` و`src/server.ts` معًا

لإضافة مورد جديد: أنشئ `schemas.ts` و`serializers.ts` و`routes.ts` داخل `src/modules/<resource>`، ثم مرر اعتماداته من `buildApp`. أضف حالة اختبار من `app.inject`، حدث OpenAPI وREADME ودليل هذا الملف. لا تجعل module يستورد نقطة التركيب.

## دليل الوثائق

### `docs/ARCHITECTURE.md`

مسؤول عن شرح الوحدات والاعتماد ودورة الطلب والمعاملات والويب هوك والإغلاق، مع Mermaid. يعتمد عليه المطور عند فهم التصميم؛ وسّعه عندما يتغير اتجاه بيانات أو lifecycle. لا تكرر المصدر كاملًا ولا تصف حدود worker الحالية على أنها ضمان موزع.

### `docs/FILE_GUIDE.md`

هذا الملف مرجع تعليمي عربي. يشرح سبب وجود الوحدات وتدفقها وأمانها وأمثلة توسعتها. أضف ملفًا إلى الدليل عند إنشاء وحدة كبيرة جديدة، وحافظ على identifiers والكود بالإنجليزية. تجنب نسخ المصدر أو كتابة خطوات تختلف عن التنفيذ.

### `README.md`

مرجع تشغيل سريع يطابق `package.json` و`.env.example`: التثبيت، الأوامر، المسارات، auth، قاعدة البيانات، والتوقيع. يعتمد عليه مستخدم API جديد. عند تغيير script أو env أو endpoint عدّل الجدول والمثال، ولا تضف قيمة غير موجودة في المخطط.
