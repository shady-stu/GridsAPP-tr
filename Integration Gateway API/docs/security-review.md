# Security review

This is an MVP security review, not a production certification. Relevant OWASP API Security Top 10 risks and controls:

| Risk                                                 | Current controls                                                                                                                                                           | Remaining gaps                                                                                                                  |
| ---------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| API1 Broken Object Level Authorization               | Queries scope customer/order reads and updates to authenticated owner, except server-derived admin; inaccessible IDs return 404. Order creation checks customer ownership. | Only one demo customer identity is configured; add a real tenant/identity model and broader adversarial tests.                  |
| API2 Broken Authentication                           | Protected resources require configured bearer tokens; unknown tokens are rejected.                                                                                         | Static demo tokens have no rotation/revocation, login, MFA, or issuer validation. Use an identity provider and managed secrets. |
| API3 Broken Object Property Level Authorization      | Zod strict request objects reject unexpected fields; response serializers expose explicit fields.                                                                          | Add schema/version governance and property-level policy review as resource fields grow.                                         |
| API4 Unrestricted Resource Consumption               | Fastify rate limiting and 1 MB body cap; pagination bounds and maximum list size.                                                                                          | Rate limiter is process-local. Add distributed limiting, concurrency caps, and infrastructure-level request/time limits.        |
| API5 Broken Function Level Authorization             | Server-derived roles; customer deletion is admin-only.                                                                                                                     | Role set is hardcoded for demonstration. Add a centrally governed policy and audit trail.                                       |
| API6 Unrestricted Access to Sensitive Business Flows | Order creation is principal-scoped and idempotent; route throttling applies.                                                                                               | No fraud, velocity, or business quotas. Add risk-based limits before exposing order creation publicly.                          |
| API7 Server Side Request Forgery                     | No outbound HTTP or user-controlled URL fetch exists.                                                                                                                      | Reassess if external provider callbacks or integrations are introduced.                                                         |
| API8 Security Misconfiguration                       | Environment is validated at startup, errors are sanitized, auth/signature headers are redacted.                                                                            | Add TLS termination, secure deployment headers, secret manager, hardened production logging and config review.                  |
| API9 Improper Inventory Management                   | Versioned `/api/v1` routes and generated OpenAPI document.                                                                                                                 | Add CI checks and lifecycle policy for deprecated API versions.                                                                 |
| API10 Unsafe Consumption of APIs                     | No third-party HTTP calls are made.                                                                                                                                        | Add explicit timeouts, response validation, and destination allowlists if provider calls are implemented.                       |

Additional safeguards: HMAC-SHA256 over exact raw bytes, constant-time signature comparison, bounded timestamp freshness, unique webhook event IDs, SQLite transaction for order plus idempotency response, unique `(principal,key)` scope, parameterized SQL, and allowlisted sort columns. Webhook events persist before acknowledgement and retries have a cap/dead-letter status.

## Production hardening checklist

- Replace static tokens with standards-based identity, short-lived credentials, revocation, and tested object/tenant policies.
- Deploy TLS, managed secrets, key rotation overlap, secret audit, distributed rate limiting, and request timeouts.
- Coordinate durable worker claims/leases or a managed queue before using multiple replicas; instrument retries and dead letters.
- Set idempotency retention and cleanup policy; add database backup encryption and restore tests.
- Add security headers at the edge, structured audit logging, metrics/alerts, dependency scanning, and CI security checks.
- Review data retention, privacy, abuse controls, and provider-specific webhook canonicalization requirements.
